Generated by `scripts/make_training_export.py` from all harvested datasets

| file | rows | what it is |
|---|--:|---|
| `train.jsonl` | 341 | **supervised pairs** (spectra → structure), 80% |

The 80/20 split is by **unique molecule** (deduped on InChIKey), so the same
structure never appears in both train and test → no leakage.

## Row schema (train/test) — maps 1:1 onto Spectro's inputs

```json
{
  "id":      "InChIKey",                       // dedup / join key
  "smiles":  "CCOC(=O)[C@@H]1CCC[C@H]1N",      // RDKit-canonical
  "selfies": "[C][C][O][C][=Branch1]...",      // ← MODEL TARGET (decoder output)
  "h_nmr":   "δ 4.15 (2H, q), 3.43 (1H, dd), ...",   // ← 1H text  → LLM2Vec
  "c_nmr":   "δ 175.5 (1C, s), 60.6 (1C, s), ...",   // ← 13C text → LLM2Vec
  "ir_bands_cm-1": [3024, 1715, 1602],         // ← IR (see caveat 2)
  "nist_ir_jdx":   null,                        // path to full IR curve, if joined
  "source_doi": "10.3762/bjoc.15.48"           // provenance
}
```

`h_nmr` / `c_nmr` are already in Spectro's `δ <shift> (<count><nucleus>, <mult>)`
ordering, ready for the text encoder. `selfies` is the decoder target; recover
SMILES with `selfies.decoder(...)` (round-trips 100% here).

## Caveats — please read before training

1. **Supervised data is the limiting axis (426 pairs).** ~78% of harvested
   records have NMR (and often IR) but **no structure label**, because many SIs
   print only a compound *label* (`3a`), not an IUPAC name OPSIN can resolve.
   (Improving the name→structure capture already took this from 190 → 426.) Those
   records
   are in `pretrain_nmr.jsonl` (useful for self-supervised NMR-encoder
   pretraining, which needs no target) but **cannot** train the supervised
   spectra→structure task. Growing the 190 is the #1 lever (see below).

2. **IR here is a band list, not a curve.** Spectro's `j-IR-vis` is a CNN over a
   *plotted IR spectrum*. The paper-sourced `ir_bands_cm-1` are **peak
   positions**, not a continuous transmittance curve. Three options:
   - featurize bands directly (multi-hot over binned wavenumbers, or the
     functional-group vector that j-IR-vis itself predicts) — simplest;
   - synthesize a curve (Lorentzians at each band) to feed the existing CNN;
   - use **real NIST JDX curves** (`scripts/nist_ir_demo.py`, full 880-pt
     spectra) — but only common molecules are in NIST (0 of the 190 here), so
     this mainly helps a common-molecule slice.
   The `pretrain_nmr.jsonl` + band lists are still fine for an **NMR-only**
   baseline (which is most of Spectro's signal anyway).

3. **¹³C integration is defaulted to `1C`.** Papers rarely report equivalent-
   carbon counts; if you want true `(nC)` values, back-fill from the SMILES
   symmetry (RDKit `CanonicalRankAtoms`).

## Data quality (so you can trust it)

Audited by `spectro_scraper/quality.py` (structure-aware):
`1H` shifts **99.97%** in-range, `13C` **100%**, IR bands **100%** in 400–4000;
**0** records with more ¹³C signals than carbons; ¹³C signals/symmetry-unique
median **1.0**; **SELFIES→SMILES round-trip 100%**; **0** InChIKey duplicates.
Run `python -m spectro_scraper.quality data/multihost/spectra.jsonl`.

## How to grow the supervised set (highest-leverage next step)

The bottleneck is **name → SMILES**, not scraping. To 5–10× the 190 pairs:
- parse the compound-label → structure mapping from the paper's **schemes/tables**
  (OCR the drawn structures, or read author-deposited SMILES/MOL in the SI);
- **PubChem** name/synonym lookup as an OPSIN fallback;
- target journals that print full IUPAC names in the experimental header.

Each resolved structure turns existing (already-scraped, already-clean) NMR/IR
into a new training pair — cheap, since the spectra are already in hand.
